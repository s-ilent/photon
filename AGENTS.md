# AGENTS.md

This file is a guide for AI coding agents working in this repository. It assumes the reader knows nothing about the project.

---

## 1. Project Overview

**Photon** (crate/binary name: `photon`) is a fast, hardware-accelerated image viewer and browser written in Rust. The product name is "Photon" even though the repository directory is named `PyImageBrowser` (a legacy name; there is no Python in this project).

Core philosophy: zero-latency paging through folders of images (tens of thousands of files), with the UI getting out of the way. The GUI is immediate-mode (`egui`) rendered on top of a `wgpu` surface; images are uploaded as GPU textures and drawn by `egui`'s painter.

- **Language:** Rust 2021 edition. Toolchain used for development: Rust 1.97.0.
- **License:** MIT OR Apache-2.0.
- **Repository:** https://github.com/s-ilent/photon
- **Author note (from README):** As of 0.1.0, almost all code is AI-generated.

### Supported image formats

Formats selectable in the file dialog and recognized by the directory walker (`src/dir_walker.rs`):
`png`, `jpg`, `jpeg`, `gif`, `bmp`, `tiff`, `tif`, `webp`, `dds`, `exr`.

Most decoding is performed by the `image` crate (features enabled in `Cargo.toml`), which decodes everything to RGBA8 on the CPU before GPU upload. `.dds` files are the exception: `image_loader::load_dds` routes them through `image_dds` (BC1–BC7, uncompressed, and DX10-header files) and decodes **every layer** — cubemap faces in DirectX order (+X, -X, +Y, -Y, +Z, -Z) and texture-array entries — as separate RGBA buffers (`DecodedImage.layers`, capped at 64 layers). The worker uploads each layer as its own `Rgba8Unorm` texture; `PhotonApp::layer_texture_ids`/`current_layer` track the displayed one and the bottom bar shows face/layer buttons. The loader worker additionally rejects images whose width or height exceed `device.limits().max_texture_dimension_2d` (or are zero), surfacing an error overlay instead of failing asynchronously in wgpu validation. Note: the ambitious "upload BC1–BC7 DDS compressed bytes straight to VRAM" plan in `Plan.md` is **not** what the current code does — the pipeline decodes to RGBA8 and uploads as `Rgba8Unorm`, mip 0 only. Treat `Plan.md` and `iced.md` as historical design notes, not as a description of current behavior.

## 2. Build, Run, and Test Commands

Run in release mode — debug builds print a warning and image decoding is slow:

```bash
# Run with an optional folder/file path argument
cargo run --release -- /path/to/image/directory

# Build the optimized binary (output: target/release/photon)
cargo build --release

# Run the (small) test suite
cargo test --release

# Lint
cargo clippy --release
```

There is no separate workspace; `Cargo.toml` is a single binary package. `dist-workspace.toml` exists only to configure `cargo-dist` for releases and marks `cargo:.` as a workspace member for that tool.

### Release profile (`Cargo.toml`)

```toml
[profile.release]
opt-level = 3
lto = true
codegen-units = 1
strip = true

[profile.dist]
inherits = "release"
lto = "thin"
```

### Release / CI

Releases are driven by `cargo-dist` (v0.32.0) via `.github/workflows/release.yml`, triggered by pushing a SemVer-looking git tag (e.g. `v0.1.0`). CI builds for `aarch64-apple-darwin`, `x86_64-apple-darwin`, `aarch64-unknown-linux-gnu`, `x86_64-unknown-linux-gnu`, and `x86_64-pc-windows-msvc`, and produces a shell installer. Do not edit `release.yml` by hand — it is autogenerated by `cargo-dist`.

## 3. Architecture and Module Layout

All source lives under `src/`. The binary entry point is `src/main.rs`.

```
src/
├── main.rs              # Entry point. eframe::App impl (App::ui), input/shortcut handling, top/bottom panels, sidebar.
├── app.rs               # PhotonApp state struct + shared types (Priority, WorkerMessage, LoadResult, StatusOverlay, SaveStatus, MouseMode, SortMode, ZoomReset, AppSettings, CachedTextures). Module root for the app/ submodule.
├── dir_walker.rs        # DirWalker: fast non-recursive (max_depth=1, non-hidden) scan of supported image files.
├── image_loader.rs      # load_image(): DDS via image_dds, everything else via the image crate; returns DecodedImage (one RGBA8 buffer per layer).
└── app/
    ├── loader.rs        # Worker thread + GPU texture upload, LRU texture cache, speculative neighbor preload, directory load, sorting.
    ├── canvas.rs        # Image workspace: zoom/pan/selection drawing, checkerboard background, input handling per mouse mode, status overlays.
    ├── clipboard.rs     # Copy (with optional crop from selection) and paste via arboard; current_rgba() source of truth for displayed bytes.
    ├── config.rs        # Settings persistence: config.ron via serde + RON, config dir via the directories crate.
    ├── saver.rs         # Save / Save Selection As: rfd save-as dialog, background encode, bottom-bar status feedback.
    └── theme.rs         # Dracula color theme + custom font loading from ../font.ttf.
```

### Key types and enums (in `src/app.rs`)

- `PhotonApp` — the central state struct (texture cache, worker channels, zoom/pan/selection, settings, GPU device/queue/render_state handles). Fields are `pub(crate)` and methods are `pub(crate)`; the crate is a binary, so there is no public API.
- `Priority::{Active, Preload}` — worker request priority. `Active` is the image the user is currently viewing; `Preload` is the speculative neighbor load.
- `WorkerMessage::{Load(LoadRequest), Paste { rgba, width, height }}` — messages sent to the loader worker thread.
- `LoadResult::{Loaded, Failed}` — worker results. `Loaded` carries the `TextureView`, dimensions, and the decoded `rgba` for `Active`/`Paste` results (`None` for `Preload`, so the bounded result channel doesn't pin several full-size buffers). `Failed` carries an `is_format_error` flag that selects `StatusOverlay::UnsupportedFormat` vs `Error`.
- `StatusOverlay::{NoImages, Loading(String), Error(String), UnsupportedFormat(String)}` — center-screen overlay states; loader failures for the active target land in `PhotonApp::error_overlay` (cleared on navigation/paste/dir load).
- `SaveStatus` — transient bottom-bar message for save success/failure (set by `app/saver.rs`, polled via `check_save_status`).
- `MouseMode::{Browse, Navigate, Select}` — cycles with Tab/Backslash. Changes how mouse input is interpreted (see canvas.rs).
- `SortMode` — six modes (alphabetical, alphabetical desc, date modified newest/oldest, file size largest/smallest). Applied to `self.images` in `sort_images`.
- `AppSettings` — user-facing settings exposed in the Settings window (theme, font size, scale-to-fit, sharp scaling, checkerboard background, keep zoom, sort mode).

### Runtime architecture (concurrency model)

There are two background threads plus the main (render) thread, connected by `std::sync::mpsc` channels:

1. **Directory walker thread** (`load_directory` in `app/loader.rs`): spawned when a folder is opened, builds a `Vec<PathBuf>` via `DirWalker`, sorts it, sends the result back on a channel. The main thread polls it in `check_dir_load_complete` each frame.
2. **Image loader worker thread** (`init_worker` in `app/loader.rs`): long-lived thread that owns a clone of the wgpu `Device`/`Queue`. It receives `WorkerMessage`s on a channel, maintains a `VecDeque` of pending requests, drops stale `Active` requests that don't match the current target id, and prioritizes `Active`/`Paste` over `Preload`. It rejects images exceeding the GPU's max texture dimension (or zero-extent) with `LoadResult::Failed`, otherwise decodes the image, `device.create_texture`s it as `Rgba8Unorm`, `queue.write_texture`s the RGBA bytes, and sends back a `LoadResult::Loaded` (view + dims + decoded bytes for Active/Paste) on a `sync_channel(5)` (bounded so it backpressures the worker).
3. **Main render thread** (`check_load_complete` in `app/loader.rs`): each frame drains the result channel, registers the `TextureView` with egui's `wgpu` renderer, evicts from the LRU texture cache (capacity 24) freeing GPU textures, and updates the displayed image if this was the active target. Failed loads for the active target set `error_overlay`. `check_dir_load_complete` and `check_save_status` poll the directory walker and save-encoder channels the same way.

`request_current` always issues an `Active` load for the current index and `Preload` loads for `images[current±1]`, skipping anything already in the texture cache. The `latest_req_id` atomic counter lets the worker discard superseded `Active` requests when the user navigates quickly. `PhotonApp::active_rgba` keeps the active image's decoded bytes so copy/save don't re-decode from disk; it is cleared whenever the target changes and on cache-hit loads (which never pass through the worker — `current_rgba` falls back to a re-decode then).

Zoom/pan reset on image switch per the configured `ZoomReset` setting (`always` / `dimension_change` / `never`, default `dimension_change`) — see the tests in `app/loader.rs`. All settings persist to `config.ron` (serde + RON, `#[serde(default)]` so partial files load; directory from the `directories` crate, overridable with `PHOTON_CONFIG_DIR`). Settings are rewritten only when they actually change, so hand edits survive while nothing is touched.

All concurrency is raw `std::thread` + `mpsc`; the previously-listed unused dependencies (`tokio`, `chrono`, `parking_lot`, `bytemuck`, `thiserror`) have been removed from `Cargo.toml` (roadmap entries for reintroducing each live in `Todo.md`). Current extras: `image_dds` (DDS decode), `serde`/`ron` (config), `directories` (config dir), `log`/`env_logger` (diagnostics), `egui-phosphor` (icon font).

### GPU/textures

The app stores wgpu state from eframe's `CreationContext` (`device`, `queue` wrapped in `Arc`, and the full `RenderState`). Uploaded image textures are `wgpu::TextureFormat::Rgba8Unorm` with `TEXTURE_BINDING | COPY_DST` usage. The texture is registered with egui's renderer via `renderer.register_native_texture(..., FilterMode::Linear)` and displayed through `painter.image(...)`. GPU texture lifecycle is managed manually through `renderer.free_texture(...)` on cache eviction and directory reload — leaks are a real concern here, so be careful when touching the cache or load paths.

### Mouse modes and input

- **Browse** (default): scroll wheel zooms (log-scale, clamped 0.1–50, around the cursor); left/middle drag pans.
- **Navigate**: scroll wheel navigates next/prev (with a 30-unit accumulator threshold); middle drag pans.
- **Select**: left-drag draws a box in screen space, converted to image space via the current scale/pan; the box is used by `copy_to_clipboard` to crop the copied image.

### Custom font and theme

`font.ttf` at the repo root is `include_bytes!`'d in `theme.rs` and inserted as the first priority in both the `Proportional` and `Monospace` font families. The dark theme is a hand-rolled Dracula palette applied via `ctx.set_visuals(...)` on the first frame (guarded by a `static AtomicBool STARTUP` in `main.rs`). Light mode uses egui defaults. Font size is adjustable in Settings and re-applies the theme.

## 4. Keyboard Shortcuts

Defined in `src/main.rs` via `egui::KeyboardShortcut` and `Modifiers::COMMAND` (Cmd on macOS, Ctrl elsewhere):

| Action | Shortcut |
| --- | --- |
| Open file/folder | `Cmd/Ctrl + O` (also the "Open" button) |
| Save as… | `Cmd/Ctrl + S` (save-as dialog; "Save Selection As…" is button-only in Select mode) |
| Copy (or crop-copy if a selection exists) | `Cmd/Ctrl + C` |
| Paste image | `Cmd/Ctrl + V` |
| Next image | `Space` / `Right Arrow` |
| Previous image | `Backspace` / `Left Arrow` |
| Cycle mouse mode | `Tab` / `Backslash` |

GOTCHA: egui-winit rewrites `Cmd/Ctrl+C`, `V`, and `X` into `egui::Event::Copy`/`Paste`/`Cut` at the input layer — the key events never exist on winit platforms. Copy/paste are therefore dispatched from those command events (plus key-shortcut fallbacks) in `take_shortcut_actions` (`src/main.rs`), which has synthetic-input tests. If a TextEdit is ever added, it will not see Ctrl+C/V — handle it there deliberately.

## 5. Testing

The suite is **twenty-one unit tests** across six files, all pure-CPU:

- `main.rs` — shortcut dispatch (`take_shortcut_actions`): clipboard command events (`Event::Copy`/`Paste`), Ctrl+C/V key fallbacks, navigation/mode shortcuts, no false positives — run against a bare `egui::Context` fed synthetic `RawInput`.
- `dir_walker.rs` — `test_is_supported_image` (extension recognition).
- `image_loader.rs` — DDS roundtrip of an in-memory uncompressed RGBA8 DDS; a cubemap test asserting all six faces decode in file order (and `is_cubemap` is set); a DX10 3-layer array test.
- `app/clipboard.rs` — three `crop_rgba` tests (empty rect, single pixel, clamping) and a `current_rgba` test for following the displayed layer.
- `app/saver.rs` — PNG and JPEG encoders write decodable files (JPEG drops alpha).
- `app/loader.rs` — zoom-reset semantics (`ZoomReset::DimensionChange`/`Never`/`Always`) on cached loads, exercised through `request_current` without a GPU.
- `app/config.rs` — RON config: empty file → defaults, roundtrip, partial file fills defaults, malformed file → defaults.

There are no integration tests and no test harness for the actual GPU/worker upload path (which needs a live wgpu device). When adding behavior to pure, side-effect-free functions (path filtering, crop math, encoder wrappers, cache-hit state transitions, config parsing), add `#[cfg(test)]` unit tests next to the code, matching the existing pattern. Do not attempt to unit-test code that requires a live wgpu device or an egui context.

Run tests with `cargo test --release` (debug builds are slow to compile and run here).

## 6. Code Style and Conventions

- **Idiomatic Rust**, rustfmt defaults. The `.gitignore` mentions rustfmt `*.rs.bk` backups, so `cargo fmt` is the expected formatter.
- `pub(crate)` visibility for everything inside the crate (it is a binary; there is no library API).
- Module conventions:
  - `mod` declarations in `src/main.rs` (`app`, `dir_walker`, `image_loader`) and in `src/app.rs` (`canvas`, `clipboard`, `loader`, `saver`, `theme`).
  - Functionality for `PhotonApp` is split across `impl PhotonApp` blocks in the `app/*.rs` files by concern, not in one big file.
- Error handling: the application uses **string errors** (`Result<_, String>` in `image_loader::load_image` and the saver) and `println!` for background-thread diagnostics rather than `anyhow`/`thiserror`. Match the surrounding pattern; do not introduce a new error type unless the task requires it.
- Diagnostics go through the **`log` facade + `env_logger`** (default filter `photon=info,warn` so dependency crates like zbus/wgpu stay quiet; `RUST_LOG` overrides). Use `log::debug!`/`info!`/`warn!`/`error!` — no raw `println!` diagnostics.
- eframe/egui 0.34 APIs are used (e.g. the unified `egui::Panel::top/bottom/left` with `show_inside` from `App::ui`, `ComboBox::from_id_salt`, `TexelCopyTextureInfo`/`TexelCopyBufferLayout`, `StrokeKind::Outside`, `TextWrapMode::Extend`). The wgpu version is 29. Match these API versions exactly; do not pull in newer or older wgpu APIs.
- When editing existing code, follow `CLAUDE.md` (in the repo root): surface assumptions, prefer the minimum change that solves the problem, touch only what the task requires, match surrounding style, and do not delete pre-existing dead code — mention it instead. (The `CLAUDE.md` file also contains a strict instruction: never suggest "let's go with a simpler approach"; if stuck, ask for clarification.)

### Known minor issues (do not "fix" unless asked)

- The build and `cargo clippy --release` are currently **warning-free**; keep it that way.
- The loader worker classifies decode errors for the overlay by **string prefix** (`"Failed to decode"` → UnsupportedFormat) between `image_loader.rs` and `app/loader.rs` — brittle but intentional; keep the prefixes in sync if you touch either side.
- `Todo.md` is the live worklist (open feature gaps, perf items, deferred shader-pass work). Check it before planning changes.

## 8. Security and Operational Considerations

- Photon is a local-only desktop application. It reads files from disk the user selects via `rfd` dialogs or passes as a CLI argument; it does not perform network access beyond what the GUI/graphics stack and the OS clipboard require.
- Clipboard operations (`arboard` with the `wayland-data-control` feature) copy/paste raw image bytes. Copy, save-as, and save-selection resolve bytes through `current_rgba` (`app/clipboard.rs`), which prefers the loader's already-decoded `active_rgba`/`pasted_rgba` and only re-reads from disk as a fallback — keep it that way rather than re-decoding.
- The worker thread holds `Arc` clones of the wgpu `Queue`; the GPU texture objects are reference-counted by egui's renderer and must be explicitly freed via `renderer.free_texture`. Texture leaks are the main resource-safety concern — be careful when modifying the LRU eviction path in `check_load_complete` or `load_directory`.
- There is no untrusted-input parsing of exotic file formats beyond what the `image` crate itself handles; treat format-decoding bugs as upstream concerns.

## 9. Quick Start for an Agent

1. Read `CLAUDE.md` for behavioral rules.
2. `cargo build --release` to confirm the tree compiles (expect zero warnings, no errors).
3. `cargo test --release` to confirm the ten unit tests pass.
4. For runtime work, `cargo run --release -- /some/folder/of/images` to launch.

Note for agents running inside the ZCode desktop app: the sandbox rewrites `argv[0]`, which breaks rustup's proxy dispatch — invoke toolchain commands as `env cargo build --release` etc.

When in doubt about whether a `Plan.md`/`iced.md` feature actually exists, trust the source code in `src/` over the design docs.
