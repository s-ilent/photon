# AGENTS.md

This file is a guide for AI coding agents working in this repository. It assumes the reader knows nothing about the project.

---

## 1. Project Overview

**Photon** (crate/binary name: `photon`) is a fast, hardware-accelerated image viewer and browser written in Rust. The product name is "Photon" even though the repository directory is named `PyImageBrowser` (a legacy name; there is no Python in this project).

Core philosophy: zero-latency paging through folders of images (tens of thousands of files), with the UI getting out of the way. The GUI is immediate-mode (`egui`) rendered on top of a `wgpu` surface; images are uploaded as GPU textures and drawn by `egui`'s painter.

- **Language:** Rust 2021 edition. Toolchain used for development: Rust 1.97.0.
- **License:** MIT OR Apache-2.0.
- **Repository:** https://github.com/s-ilent/photon
- **Author note (from README):** As of 0.1.0, almost all code is AI-generated.

### Supported image formats

Formats recognized by the directory walker and the file dialog, from the single
source of truth `dir_walker::SUPPORTED_EXTENSIONS`:
`png`, `jpg`, `jpeg`, `gif`, `bmp`, `tiff`, `tif`, `webp`, `dds`, `exr`, `tga`,
`pnm`, `pbm`, `pgm`, `ppm`, `ico`, `cur`, `hdr`.

Most decoding is performed by the `image` crate (features enabled in `Cargo.toml`), which decodes everything to RGBA8 on the CPU before GPU upload. `.dds` files are the exception: `image_loader::load_dds` routes them through `image_dds` (BC1–BC7, uncompressed, and DX10-header files) and decodes **every layer** — cubemap faces in DirectX order (+X, -X, +Y, -Y, +Z, -Z) and texture-array entries — as separate RGBA buffers (`DecodedImage.layers`, capped at 64 layers). The worker uploads each layer as its own `Rgba8Unorm` texture; `PhotonApp::layer_texture_ids`/`current_layer` track the displayed one and the bottom bar shows face/layer buttons. The loader worker additionally rejects images whose width or height exceed `device.limits().max_texture_dimension_2d` (or are zero), surfacing an error overlay instead of failing asynchronously in wgpu validation. Note: the ambitious "upload BC1–BC7 DDS compressed bytes straight to VRAM" plan in `Plan.md` is **not** what the current code does — the pipeline decodes to RGBA8 and uploads as `Rgba8Unorm`, mip 0 only. Treat `Plan.md` and `iced.md` as historical design notes, not as a description of current behavior.

## 2. Build, Run, and Test Commands

Run in release mode — debug builds print a warning and image decoding is slow:

```bash
# Run with an optional folder/file path argument
cargo run --release -- /path/to/image/directory

# Build the optimized binary (output: target/release/photon)
cargo build --release

# Run the (small) test suite
cargo test --release

# Lint
cargo clippy --release
```

There is no separate workspace; `Cargo.toml` is a single binary package. `dist-workspace.toml` exists only to configure `cargo-dist` for releases and marks `cargo:.` as a workspace member for that tool.

### Release profile (`Cargo.toml`)

```toml
[profile.release]
opt-level = 3
lto = true
codegen-units = 1
strip = true

[profile.dist]
inherits = "release"
lto = "thin"
```

### Release / CI

Releases are driven by `cargo-dist` (v0.32.0) via `.github/workflows/release.yml`, triggered by pushing a SemVer-looking git tag (e.g. `v0.1.0`). CI builds for `aarch64-apple-darwin`, `x86_64-apple-darwin`, `aarch64-unknown-linux-gnu`, `x86_64-unknown-linux-gnu`, and `x86_64-pc-windows-msvc`, and produces a shell installer. Do not edit `release.yml` by hand — it is autogenerated by `cargo-dist`.

## 3. Architecture and Module Layout

All source lives under `src/`. The binary entry point is `src/main.rs`.

```
src/
├── main.rs              # Entry point. `fn main()` bootstrap + `impl eframe::App` (delegates panel bodies to ui/ and dispatches commands).
├── input.rs             # Shortcut scanner: `take_commands(ctx)` reads the command registry's binding table off egui input (incl. the Ctrl+C/V command-event gotcha).
├── commands.rs          # Command registry (Roadmap §1): `Command` enum, `default_bindings()`, `PhotonApp::run_command()` — the single key→action table.
├── ui.rs                # Module root for the ui/ submodule.
├── app.rs               # PhotonApp state struct + shared types (Priority, WorkerMessage, LoadResult, StatusOverlay, SaveStatus, MouseMode, SortMode, ZoomReset, AppSettings). Module root for the app/ submodule.
├── dir_walker.rs        # DirWalker + `SUPPORTED_EXTENSIONS` (single source of truth for recognised formats; reused by the Open dialog): fast non-recursive (max_depth=1, non-hidden) scan of supported image files.
├── image_loader.rs      # load_image() -> Result<DecodedImage, DecodeError>: DDS via image_dds, everything else via the image crate with Exif orientation applied at decode (upright pixels, dimensions swapped for 90/270); one RGBA8 buffer per layer.
├── render.rs            # Image canvas render pass: WGSL pipeline, tile chunking, DrawImageCallback (see "GPU / render pipeline") + the headless GPU test harness (`#[cfg(test)] mod gpu_tests`).
├── ui/
│   ├── toolbar.rs       # Top panel body (open/copy/paste/save, mouse mode, sidebar toggle, prev/next).
│   ├── info_bar.rs      # Bottom info bar (index, filename, dimensions, zoom, save status, layer/face selector).
│   ├── sidebar.rs       # Left file-list sidebar (sort combo + virtualized rows).
│   ├── settings_window.rs # Settings window body.
│   ├── batch_window.rs  # Batch Convert window: file list, format/quality/folder, operation chain, non-blocking run + per-file status.
│   └── overlay.rs       # Centre-screen status overlay (spinner / error / unsupported) + loading text.
└── app/
    ├── loader.rs        # Worker thread (decode + GPU tile upload), LRU texture cache, speculative neighbor preload, directory load + watcher, sorting.
    ├── canvas.rs        # Image workspace: zoom/pan/selection drawing, checkerboard background, input handling per mouse mode.
    ├── view.rs          # Fit/zoom geometry (Roadmap §3): FitMode, fit_zoom, zoom_limits (adaptive, image-derived), zoom_to_fill, ZoomLock, image_pixel_at, html_hex, tile_offsets. fit/zoom + pixel readout + tile-repeat wired into canvas/info bar; ZoomLock awaits the Settings UI.
    ├── settings.rs      # AppSettings + SortMode + ZoomReset (split out of app.rs), re-exported from app.rs so paths are unchanged.
    ├── batch.rs         # Batch conversion engine (Roadmap §5): Operation chain, OutputFormat, ConversionJob, convert_file/run_batch (`rayon` par_iter driver). Driven by the Batch Convert window.
    ├── edit.rs          # Interactive editing ops + bounded whole-image undo (Roadmap §4): rotate/flip/crop/grayscale/negative over RGBA8. Pure; not yet wired to the canvas.
    ├── clipboard.rs     # Copy (with optional crop from selection) and paste via arboard; current_rgba() source of truth for displayed bytes.
    ├── config.rs        # Settings persistence: config.ron via serde + RON, config dir via the directories crate.
    ├── saver.rs         # Save / Save Selection As: rfd save-as dialog, background encode, bottom-bar status feedback.
    └── theme.rs         # Dracula color theme + custom font loading from ../font.ttf.
```

### Key types and enums (in `src/app.rs` and `src/app/settings.rs`)

- `PhotonApp` — the central state struct (texture cache, worker channels, zoom/pan/selection, settings, GPU device/queue/render_state handles). Fields are `pub(crate)` and methods are `pub(crate)`; the crate is a binary, so there is no public API.
- `Priority::{Active, Preload}` — worker request priority. `Active` is the image the user is currently viewing; `Preload` is the speculative neighbor load.
- `WorkerMessage::{Load(LoadRequest), Paste { rgba, width, height }}` — messages sent to the loader worker thread.
- `LoadResult::{Loaded, Failed}` — worker results. `Loaded` carries the `TextureView`, dimensions, and the decoded `rgba` for `Active`/`Paste` results (`None` for `Preload`, so the bounded result channel doesn't pin several full-size buffers). `Failed` carries an `is_format_error` flag that selects `StatusOverlay::UnsupportedFormat` vs `Error`.
- `StatusOverlay::{NoImages, Loading(String), Error(String), UnsupportedFormat(String)}` — center-screen overlay states; loader failures for the active target land in `PhotonApp::error_overlay` (cleared on navigation/paste/dir load).
- `SaveStatus` — transient bottom-bar message for save success/failure (set by `app/saver.rs`, polled via `check_save_status`).
- `MouseMode::{Browse, Navigate, Select}` — cycles with Tab/Backslash. Changes how mouse input is interpreted (see canvas.rs).
- `SortMode` — six modes (alphabetical, alphabetical desc, date modified newest/oldest, file size largest/smallest). Applied to `self.images` in `sort_images`.
- `AppSettings` (in `app/settings.rs`) — user-facing settings exposed in the Settings window (theme, font size, scale-to-fit, sharp scaling, checkerboard background, tile-repeat, zoom-reset, fit mode, sort mode). Re-exported from `app.rs`.

### Runtime architecture (concurrency model)

There are two background threads plus the main (render) thread, connected by `std::sync::mpsc` channels:

1. **Directory walker thread** (`load_directory` in `app/loader.rs`): spawned when a folder is opened, builds a `Vec<PathBuf>` via `DirWalker`, sorts it, sends the result back on a channel. The main thread polls it in `check_dir_load_complete` each frame.
2. **Directory watcher thread** (also `load_directory`): a `notify-debouncer-full` watcher (non-recursive, 500ms debounce) that re-walks the directory on changes and sends fresh listings on its own channel (`check_dir_watch` → `apply_dir_refresh`). Refreshes preserve the user's place: the displayed image stays selected by path and is **not reloaded unless its mtime changed on disk** (then the stale cache entry is freed and re-requested). A replaced watcher stops the old thread via a dropped stop-sender; refreshes are skipped while the initial walk is in flight and ignored when the listing is unchanged.
3. **Image loader worker thread** (`init_worker` in `app/loader.rs`): long-lived thread that owns a clone of the wgpu `Device`/`Queue`. It receives `WorkerMessage`s on a channel, maintains a `VecDeque` of pending requests, drops stale `Active` requests that don't match the current target id, and prioritizes `Active`/`Paste` over `Preload`. It rejects images exceeding the GPU's max texture dimension (or zero-extent) with `LoadResult::Failed`, otherwise decodes the image, uploads **every layer** as its own `Rgba8Unorm` texture (each registered with linear AND nearest samplers), and sends back a `LoadResult::Loaded` on a `sync_channel(5)`. Non-target results are cached but never displayed (no neighbor-pixel intermediates).
4. **Main render thread** (`check_load_complete` in `app/loader.rs`): each frame drains the result channel, registers the `TextureView`s with egui's `wgpu` renderer, evicts from the LRU texture cache (capacity 24) freeing GPU textures, and updates the displayed image if this was the active target. Failed loads for the active target set `error_overlay`. `check_dir_load_complete`, `check_dir_watch`, and `check_save_status` poll their channels the same way.

`request_current` always issues an `Active` load for the current index and `Preload` loads for `images[current±1]`, skipping anything already in the texture cache. The `latest_req_id` atomic counter lets the worker discard superseded `Active` requests when the user navigates quickly. `PhotonApp::active_rgba` keeps the active image's decoded bytes so copy/save don't re-decode from disk; it is cleared whenever the target changes and on cache-hit loads (which never pass through the worker — `current_rgba` falls back to a re-decode then).

Zoom/pan reset on image switch per the configured `ZoomReset` setting (`always` / `dimension_change` / `never`, default `dimension_change`) — see the tests in `app/loader.rs`. All settings persist to `config.ron` (serde + RON, `#[serde(default)]` so partial files load; directory from the `directories` crate, overridable with `PHOTON_CONFIG_DIR`). Settings are rewritten only when they actually change, so hand edits survive while nothing is touched.

Viewer concurrency is raw `std::thread` + `mpsc`; the batch engine additionally uses `rayon`'s `par_iter`. The previously-listed unused dependencies (`tokio`, `chrono`, `parking_lot`, `bytemuck`, `thiserror`) have been removed from `Cargo.toml` (roadmap entries for reintroducing each live in `Todo.md`). Current extras: `image_dds` (DDS decode), `serde`/`ron` (config), `directories` (config dir), `log`/`env_logger` (diagnostics), `egui-phosphor` (icon font), `notify-debouncer-full` (directory watching), `rayon` (batch parallelism), `pollster` (dev-only; drives the async wgpu calls in the GPU tests).

### GPU / render pipeline

The image canvas draws through a **custom wgpu render pass** (`src/render.rs` + `src/render/image.wgsl`), not egui's `painter.image`: a WGSL pipeline built at startup against the surface's format (`RenderState::target_format`), registered in `renderer.callback_resources`, drawing the displayed image's **tiles** with a per-frame uniform (viewport transform, tint, sharp-sampling flag). The **loader worker** builds the GPU-resident `RenderImage` (per-layer tiles with bind groups and vertex quads) using the same bind group layouts cloned from `PhotonApp::image_renderer` — bind groups must be created from the *same layout objects* the pipeline uses. Images larger than the GPU's `max_texture_dimension_2d` are chunked (`render::chunk_grid`) and reassembled in image space; only zero-extent images fail to load.

The device requests `max_texture_dimension_2d` of 16384, clamped to what the adapter supports (the `WgpuSetupCreateNew::device_descriptor` callback in `main.rs`). Textures are `wgpu::TextureFormat::Rgba8Unorm` (CPU-decoded RGBA8; native-format upload is a future milestone). **Sampling is a shader decision**: there is exactly ONE sampler and it is **linear** — a nearest sampler must **never** be created or bound. Sharp/pixel scaling is done in `image.wgsl` by snapping the sample coordinate to the texel centre (`sharp_sample_uv`, filter box from `fwidth`), so the linear sampler returns the exact texel.

**GOTCHA — `callback_resources` is a TypeId-keyed map.** The renderer state must be registered/fetched through `ImageRendererState::insert_into` / `from_resources` (which name the `Arc<ImageRendererState>` key in one place). A raw `resources.get::<T>()` with a type that doesn't match what was inserted returns `None` — and because both `prepare` and `paint` bail on `None`, the **whole canvas silently draws nothing** (checkerboard only, no error). Always go through the helpers.

GPU lifetime is **wgpu refcounting**: the cache and `PhotonApp::displayed_image` hold `Arc<RenderImage>`, and dropping the last reference (including in-flight frames, which wgpu tracks) frees the resources. There is no manual `free_texture` bookkeeping — do not reintroduce it. egui's `TextureId` registration is no longer used for the image canvas.

**Filters**: convolution/effect filters are intended to move to a `wgpu` compute pass (`Roadmap.md` §5b), but the **CPU implementations are the retained fallback** — core functions must work without a GPU, so do not delete the CPU path, and resampling (resize) stays CPU. The `app/batch.rs` CPU engine covers the cheap chain steps (format, resize, rotate/flip, grayscale/negative).

### Mouse modes and input

- **Browse** (default): scroll wheel zooms (log-scale, clamped 0.1–50, around the cursor); left/middle drag pans. Files/folders can be drag-and-dropped onto the window to open them (`open_path`, shared with the Open dialog) — **X11 and Windows/macOS only**: winit's Wayland backend has no file drop support, so on Wayland the drop is a no-op.
- **Navigate**: scroll wheel navigates next/prev (with a 30-unit accumulator threshold); middle drag pans.
- **Select**: left-drag draws a box in screen space, converted to image space via the current scale/pan; the box is used by `copy_to_clipboard` to crop the copied image.

### Custom font and theme

`font.ttf` at the repo root is `include_bytes!`'d in `theme.rs` and inserted as the first priority in both the `Proportional` and `Monospace` font families. The dark theme is a hand-rolled Dracula palette applied via `ctx.set_visuals(...)` on the first frame (guarded by a `static AtomicBool STARTUP` in `main.rs`). Light mode uses egui defaults. Font size is adjustable in Settings and re-applies the theme.

## 4. Keyboard Shortcuts

Defined in `src/main.rs` via `egui::KeyboardShortcut` and `Modifiers::COMMAND` (Cmd on macOS, Ctrl elsewhere):

| Action | Shortcut |
| --- | --- |
| Open file/folder | `Cmd/Ctrl + O` (also the "Open" button) |
| Save as… | `Cmd/Ctrl + S` (save-as dialog; "Save Selection As…" is button-only in Select mode) |
| Copy (or crop-copy if a selection exists) | `Cmd/Ctrl + C` |
| Paste image | `Cmd/Ctrl + V` |
| Next image | `Space` / `Right Arrow` |
| Previous image | `Backspace` / `Left Arrow` |
| Cycle mouse mode | `Tab` / `Backslash` |
| Toggle fullscreen | `F11` |

GOTCHA: egui-winit rewrites `Cmd/Ctrl+C`, `V`, and `X` into `egui::Event::Copy`/`Paste`/`Cut` at the input layer — the key events never exist on winit platforms. Copy/paste are therefore dispatched from those command events (plus key-shortcut fallbacks) in `take_shortcut_actions` (`src/main.rs`), which has synthetic-input tests. If a TextEdit is ever added, it will not see Ctrl+C/V — handle it there deliberately.

## 5. Testing

The suite is **102 unit tests** across thirteen files (all pure-CPU except the GPU harness in `render.rs`):

- `commands.rs` — registry invariants: every `Command` has ≥1 binding row, the table names only known commands, `cli_name`s are unique and non-empty, no duplicate key binding, and Copy/Paste carry their raw-key fallbacks.
- `input.rs` — `take_commands` dispatch: clipboard command events (`Event::Copy`/`Paste`), Ctrl+C/V key fallbacks, navigation/mode/fullscreen shortcuts, two-key dedup, and no false positives — run against a bare `egui::Context` fed synthetic `RawInput`.
- `image_loader.rs` — DDS roundtrip of an in-memory uncompressed RGBA8 DDS; a cubemap test asserting all six faces decode in file order (and `is_cubemap` is set); a DX10 3-layer array test; a no-Exif decode is byte-identical; and an Exif `orientation=6` PNG fixture decodes with swapped dimensions and a rotation permutation (Roadmap §3); plus `DecodeError::is_unsupported_format` classification (Roadmap §8).
- `app/view.rs` — fit/zoom geometry (Roadmap §3): each `FitMode`, adaptive `zoom_limits`, zero-size guards, `clamp_to_limits`, `zoom_to_fill`, `ZoomLock`, plus the pixel-readout helpers (`image_pixel_at`, `html_hex`) and `tile_offsets`. Pure.
- `app/batch.rs` — the conversion engine (Roadmap §5): rotate/flip/grayscale (documented luma)/negative/resize on known buffers, `OutputFormat::extension`, overwrite-skip, and an end-to-end PNG→JPEG via `tempfile`. Pure/CPU.
- `app/edit.rs` — interactive edits (Roadmap §4): each rotation/flip on a known buffer, crop clamping, grayscale weights, negative, and undo/redo incl. bounded-capacity eviction. Pure.
- `ui/batch_window.rs` — pure helpers behind the Convert window (`build_jobs`, `status_label`, `summarize`, file-list dedup, resize-with-no-dims no-op).
- `render.rs` — tile `chunk_grid` math, the uniform struct's WGSL layout, and the **GPU harness** (`gpu_tests`): the render pipeline builds on a live adapter and a compute dispatch round-trips (both skip when no adapter).
- `dir_walker.rs` — `is_supported_image` extension recognition (including the tga/pnm/ico/hdr additions) and `SUPPORTED_EXTENSIONS` is lowercase with no duplicates.
- `app/clipboard.rs` — three `crop_rgba` tests (empty rect, single pixel, clamping) and a `current_rgba` test for following the displayed layer.
- `app/saver.rs` — PNG and JPEG encoders write decodable files (JPEG drops alpha).
- `app/loader.rs` — zoom-reset semantics (`ZoomReset::DimensionChange`/`Never`/`Always`), sharp-scaling sampler pick, and directory-refresh semantics (place preserved without reload / reload on mtime change / landing when the current file vanishes) on cached loads, exercised through `request_current`/`apply_dir_refresh` without a GPU.
- `app/config.rs` — RON config: empty file → defaults, roundtrip, partial file fills defaults (incl. `fit_mode` → `ReduceOnly`), malformed file → defaults.

There is a **headless GPU test harness** now (`src/render.rs`, `#[cfg(test)] mod gpu_tests`): `headless_device()` acquires a headless Vulkan/fallback adapter and returns `None` when unavailable, so GPU tests **skip cleanly** on a machine without one. Use that pattern for any new wgpu code (compute filters, render-pass changes) — do not unit-test code that needs an *egui* context, but wgpu code is fair game via the harness. When adding behavior to pure, side-effect-free functions (path filtering, crop math, encoder wrappers, cache-hit state transitions, config parsing), add `#[cfg(test)]` unit tests next to the code, matching the existing pattern.

Run tests with `cargo test --release` (debug builds are slow to compile and run here).

## 6. Code Style and Conventions

- **Idiomatic Rust**, rustfmt defaults. The `.gitignore` mentions rustfmt `*.rs.bk` backups, so `cargo fmt` is the expected formatter.
- `pub(crate)` visibility for everything inside the crate (it is a binary; there is no library API).
- Module conventions:
  - `mod` declarations in `src/main.rs` (`app`, `dir_walker`, `image_loader`) and in `src/app.rs` (`canvas`, `clipboard`, `loader`, `saver`, `theme`).
  - Functionality for `PhotonApp` is split across `impl PhotonApp` blocks in the `app/*.rs` files by concern, not in one big file.
- Error handling: the application uses **string errors** (`Result<_, String>` in `image_loader::load_image` and the saver) and `println!` for background-thread diagnostics rather than `anyhow`/`thiserror`. Match the surrounding pattern; do not introduce a new error type unless the task requires it.
- Diagnostics go through the **`log` facade + `env_logger`** (default filter `photon=info,warn` so dependency crates like zbus/wgpu stay quiet; `RUST_LOG` overrides). Use `log::debug!`/`info!`/`warn!`/`error!` — no raw `println!` diagnostics.
- **No selectable text**: the theme sets `style.interaction.selectable_labels = false` (both dark and light). Photon is a viewer; egui's selectable-label cursor caused offset selection rectangles and scroll-jumps. If a TextEdit is ever added, re-enable selectability locally.
- eframe/egui 0.34 APIs are used (e.g. the unified `egui::Panel::top/bottom/left` with `show_inside` from `App::ui`, `ComboBox::from_id_salt`, `TexelCopyTextureInfo`/`TexelCopyBufferLayout`, `StrokeKind::Outside`, `TextWrapMode::Extend`). The wgpu version is 29. Match these API versions exactly; do not pull in newer or older wgpu APIs.
- When editing existing code, follow `CLAUDE.md` (in the repo root): surface assumptions, prefer the minimum change that solves the problem, touch only what the task requires, match surrounding style, and do not delete pre-existing dead code — mention it instead. (The `CLAUDE.md` file also contains a strict instruction: never suggest "let's go with a simpler approach"; if stuck, ask for clarification.)

### Known minor issues (do not "fix" unless asked)

- The build and `cargo clippy --release` are currently **warning-free**; keep it that way.
- The loader worker decides the overlay via `DecodeError::is_unsupported_format()` (`image_loader.rs`), carried across the result channel as `LoadResult::Failed`'s `is_format_error` bool. When you add a decode failure path, classify it (unsupported/`InvalidData` vs a non-format error) — do not reintroduce string comparisons.
- `Todo.md` is the live worklist (open feature gaps, perf items, deferred shader-pass work). `Roadmap.md` is the long-horizon forward feature map (grouped by capability, with algorithm/CLI reference appendices). Check both before planning changes.

## 8. Security and Operational Considerations

- Photon is a local-only desktop application. It reads files from disk the user selects via `rfd` dialogs or passes as a CLI argument; it does not perform network access beyond what the GUI/graphics stack and the OS clipboard require.
- Clipboard operations (`arboard` with the `wayland-data-control` feature) copy/paste raw image bytes. Copy, save-as, and save-selection resolve bytes through `current_rgba` (`app/clipboard.rs`), which prefers the loader's already-decoded `active_rgba`/`pasted_rgba` and only re-reads from disk as a fallback — keep it that way rather than re-decoding.
- The worker thread holds `Arc` clones of the wgpu `Device`/`Queue`. GPU resources are wgpu-refcounted (`Arc<RenderImage>` in the cache / display state), so dropping the last reference frees them — there is no manual free bookkeeping. Keep it that way: reintroducing manual `free_texture`-style lifecycle on top of Arc sharing is how double-frees happen.
- There is no untrusted-input parsing of exotic file formats beyond what the `image` crate itself handles; treat format-decoding bugs as upstream concerns.

## 9. Quick Start for an Agent

1. Read `CLAUDE.md` for behavioral rules.
2. `cargo build --release` to confirm the tree compiles (expect zero warnings, no errors).
3. `cargo test --release` to confirm the 102 unit tests pass.
4. For runtime work, `cargo run --release -- /some/folder/of/images` to launch.

Note for agents running inside the ZCode desktop app: the sandbox rewrites `argv[0]`, which breaks rustup's proxy dispatch — invoke toolchain commands as `env cargo build --release` etc.

When in doubt about whether a `Plan.md`/`iced.md` feature actually exists, trust the source code in `src/` over the design docs.
